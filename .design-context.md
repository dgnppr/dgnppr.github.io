# Design Context

## Service

- **Languages:** Korean-first, with English technology terms and an English resume.
- **Audience:** Recruiters, hiring managers, and experienced engineers reviewing evidence of data-platform work.
- **Brand personality:** Quietly confident, technical, evidence-led, and editorial rather than promotional.
- **Aesthetic direction:** A separate, light editorial portfolio system inspired by the resume document. It deliberately does not inherit the blog chrome or its dark theme.
- **Accessibility:** WCAG AA baseline; keyboard and touch use are first-class requirements.

## Portfolio decision

- Use a case-study index at `/work/`, not a marketing landing page or a career timeline.
- Remove the global blog header and footer from every work route. A compact document identity and an in-content resume link are enough.
- Keep a project as one Markdown document in `_portfolio/`; the list and detail page both derive from it.
- Do not expose secrets, client data, or unverifiable outcomes. Reuse only public resume evidence unless a project is explicitly expanded later.

## Reference Sites

- None. Preserve the established blog language instead of borrowing a product-site visual style.
